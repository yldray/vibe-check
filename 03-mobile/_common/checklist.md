# Mobile — common checks

- [ ] `MOB-001` **P0** No secrets in the app bundle
- [ ] `MOB-002` **P0** Tested on a real device, not only emulator / simulator
- [ ] `MOB-003` **P0** Account deletion inside the app (if the app has accounts)
- [ ] `MOB-004` **P0** Crash reporting connected (Crashlytics, Sentry)
- [ ] `MOB-005` **P1** Offline / bad network: no crash, clear message, retry
- [ ] `MOB-006` **P1** Permissions asked in context, with a clear reason; denial handled
- [ ] `MOB-007` **P1** Deep links open the right screen (cold and warm start)
- [ ] `MOB-008` **P1** Push notifications: permission, token refresh, tap opens right screen
- [ ] `MOB-009` **P1** Background → foreground keeps state
- [ ] `MOB-010` **P1** Small screen, large screen, notch, dark mode, large font
- [ ] `MOB-011` **P1** Force update / minimum version strategy
- [ ] `MOB-012` **P1** Cold start (app killed → first usable screen) under 2 seconds on a mid-range device (Android: `adb shell am start -W`; iOS: Instruments → App Launch)
- [ ] `MOB-013` **P1** The keyboard never covers the field being typed in or the Save / Submit button, on the smallest supported screen
- [ ] `MOB-014` **P1** Android back button / gesture goes back one screen and never closes the app mid-flow
- [ ] `MOB-015` **P1** Rotating the phone doesn't break the layout or lose input, or the app is locked to portrait on purpose
- [ ] `MOB-016` **P2** 10 minutes of continuous use: the phone doesn't overheat and battery use looks normal (Xcode Energy gauge, Android battery usage)
- [ ] `MOB-017` **P2** Caches have a size limit: app storage doesn't keep growing after days of use
- [ ] `MOB-018` **P1** Blind test: someone who has never seen the app can say what the home screen is for, without help
- [ ] `MOB-019` **P1** Clean install: delete the app, reinstall and walk the whole first-run flow (onboarding, permissions, login). On iOS the Keychain survives uninstall, so old tokens can come back

- [ ] `MOB-020` **P1** The new build number is one above the highest ever uploaded in App Store Connect / Play Console (every track, including builds removed from a draft or rejected), not above the local value; the marketing version in the repo equals the live store version and matches across iOS and Android
- [ ] `MOB-021` **P1** Store builds are made from a commit that is pushed and tagged, never from local changes
- [ ] `MOB-022` **P2** After a library upgrade, every `patch-package` patch still applies and `postinstall` fails loudly when one doesn't
- [ ] `MOB-023` **P1** First-run bugs are tested with empty persisted storage (clean install or cleared cache); a warm cache hides crashes such as hooks after an early return
- [ ] `MOB-024` **P0** Every certificate fingerprint a service checks includes the Play app signing key from Play Console → App integrity: the SHA-1 / SHA-256 in the Firebase Android app (and the Google Sign-In OAuth client) and in `/.well-known/assetlinks.json`. With Play App Signing, users get an APK signed by Google's key, so Google Sign-In, Firebase phone auth and App Links work in local builds and fail for everyone who installs from Play (`DEVELOPER_ERROR`, `ApiException: 10`). Test: sign in and open an App Link from a build installed through a Play testing track
- [ ] `MOB-025` **P1** No `http://` media URLs in API data: iOS often loads them through a broad ATS exception while Android's cleartext block drops them silently, so images or videos are missing only on Android. Test: query image and video fields that start with `http://` and open those items in an Android release build; fix the data or upgrade to `https://`, don't allow cleartext in the manifest
- [ ] `MOB-026` **P1** Offline downloads (if the app has them): a download continues in the background and with the screen locked, shows progress, resumes after network loss and reboot; with the app killed and airplane mode on the item plays start to end and seeks; deleting it frees the storage (check the app's storage before and after)
- [ ] `MOB-027` **P1** Every business event the web records (views, plays, starts, completions) is also sent by every mobile and TV client, once per real event. Test: do the action only in the app, check the admin report, reopen the app and confirm no duplicate
- [ ] `MOB-028` **P1** The app language resolves to a supported one: a device set to an unsupported language opens in the default language (not a third one the server happens to have); missing keys fall back to the default language; a bundled dictionary doesn't override server strings in every language. Test: device in an unsupported language, then switch in settings; no blank labels or buttons
