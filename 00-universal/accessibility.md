# Accessibility

- [ ] `A11Y-001` **P1** Every image has meaningful `alt` (or empty for decorative)
- [ ] `A11Y-002` **P1** All actions reachable by keyboard; focus is visible. Tab and screen-reader order follow the visual order (no CSS `order`, `row-reverse` or positive `tabindex` that scrambles it), and sticky headers, cookie banners and chat widgets never cover the focused element (`scroll-padding-top`) (WCAG 1.3.2, 2.4.11). Test: Tab through each main page: focus moves in reading order and never disappears under a fixed bar
- [ ] `A11Y-003` **P1** Form inputs have labels
- [ ] `A11Y-004` **P1** Text contrast at least 4.5:1 (3:1 for large text), also for text on images, placeholders and brand-colored buttons. Icons that carry meaning, input borders, focus rings and chart lines reach 3:1 against what's behind them (WCAG 1.4.11). Test: the Lighthouse or axe contrast audit lists no elements; those audits skip icons and borders and see only the current state, so check those with a color picker in hover, focus and error states, over images and in both light and dark themes
- [ ] `A11Y-005` **P2** Screen reader tested on main flow (VoiceOver / TalkBack / NVDA)
- [ ] `A11Y-006` **P2** Respects reduced motion and font scaling. Anything that moves on its own for more than 5 seconds (carousel, marquee, animated background) has a visible pause control for everyone, not only under `prefers-reduced-motion` (WCAG 2.2.2). Under reduced motion, movement turns into a crossfade or an instant change, but spinners, progress bars and state feedback stay: a global `animation-duration: 0.01ms` reset without `animation-iteration-count: 1` makes endless animations restart every frame. Native apps read the OS setting and react when it changes while the app is open, and switching transitions off must not switch off the iOS swipe-back gesture (see `MOB-032`). Test: press it and check that every moving element stops: an inline `style="animation: …"` shorthand resets `animation-play-state` to `running` and beats a stylesheet `paused` rule unless that rule is `!important`; turn Reduce Motion on while the page or app is open: loaders still show progress and nothing jumps
- [ ] `A11Y-007` **P1** Headings go down in order: one `h1`, no skipped levels (`h2` → `h4`). Pick the level by structure and the size with CSS
- [ ] `A11Y-008` **P1** Videos with speech have captions (`<track kind="captions">`); autoplaying video is muted and can be paused
- [ ] `A11Y-009` **P1** ARIA only where it's valid: no attributes the element's role doesn't allow (e.g. `aria-label` on a plain `div` or `span`), no `role` or `aria-hidden` that hides real content. Test: Lighthouse and axe report no ARIA errors
- [ ] `A11Y-010` **P1** Tap targets are big enough. On the web, at least 24×24 CSS px, or spaced so a 24 px circle centered on each one touches no other target (WCAG 2.5.8). In apps, icon buttons, close buttons, checkboxes and row actions reach 44×44 pt on iOS and 48×48 dp on Android, with padding or `hitSlop` when the icon itself is smaller. AI sizes the touch area to a 16–20 px icon, so the ✕ on a sheet or the trash icon on a row takes several tries (see `QA-020`). Test: the Lighthouse or axe target-size audit; Xcode Accessibility Inspector and Android Accessibility Scanner on the main screens; grep React Native `Pressable` and `Touchable*` with a width or height under 44 and no `hitSlop`
- [ ] `A11Y-011` **P1** Users can zoom: the viewport has no `maximum-scale=1` or `user-scalable=no` (also in framework exports such as Next.js `viewport` with `maximumScale` or `userScalable`), and inputs use at least 16px text, so iOS Safari has no reason to zoom in on focus (the usual excuse for the lock). At 200% browser zoom and at 320px width, nothing is cut off and the page doesn't scroll sideways (WCAG 1.4.4, 1.4.10). Test: grep `maximum-scale`, `user-scalable`, `maximumScale` and `userScalable`; zoom the main pages to 200%; DevTools at 320px width
- [ ] `A11Y-012` **P1** Dialogs, drawers and menus manage focus: opening moves focus inside, Tab stays inside a modal, Esc closes it, focus goes back to the control that opened it, and the page behind can't be reached (`<dialog>` with `showModal()`, or `inert` on the background plus `aria-modal`). Long pages have a "Skip to content" link (WCAG 2.1.2, 2.4.1, 2.4.3). In native apps, a modal sheet answers the escape gesture (iOS `accessibilityPerformEscape`, React Native `onAccessibilityEscape`) and has a close button a screen reader can reach. Test: open and close every dialog with the keyboard only; with a screen reader on, try to reach the page behind an open dialog; on iOS, do the VoiceOver two-finger Z gesture on each sheet
- [ ] `A11Y-013` **P1** Status changes are announced: toasts, "Saved", errors after submit and "loading finished" are in a `role="status"` or `aria-live` region (errors in `role="alert"`). Native apps announce them with `AccessibilityInfo.announceForAccessibility` in React Native (its `accessibilityLiveRegion` works only on Android), `UIAccessibility.post(notification: .announcement, …)` on iOS, a live region in Android Views or Compose, or `Semantics(liveRegion: true)` in Flutter (WCAG 4.1.3). Test: with VoiceOver, TalkBack or NVDA on, save a form, trigger a validation error and a toast: each is read out without moving focus
- [ ] `A11Y-014` **P1** Color is never the only signal: errors, required fields, statuses, chart series and links inside text also have text, an icon, a pattern or an underline (WCAG 1.4.1). In forced-colors mode (Windows contrast themes), focus rings, borders and icons stay visible; a focus ring drawn only with `box-shadow` disappears there, so add an `outline` (a `transparent` one is enough). Test: look at a grayscale screenshot of each main screen; DevTools → Rendering → emulate `forced-colors: active` and each vision deficiency
- [ ] `A11Y-015` **P1** Every control has a name a screen reader reads, and it matches the visible label: icon-only buttons and links get one (`aria-label`, React Native `accessibilityLabel`, Android `contentDescription`, Flutter `Semantics(label:)`, SwiftUI `.accessibilityLabel`); toggles and expanders expose their state (`aria-pressed`, `aria-expanded`, `accessibilityState`); link text makes sense on its own; swipe order follows the screen; custom tab bars expose tab or button traits (WCAG 4.1.2, 2.5.3, 2.4.4). Test: the Lighthouse accessible-name audits list nothing; swipe through the main screens with VoiceOver and TalkBack: no control is read as a bare "button" or "image"
- [ ] `A11Y-016` **P1** Nothing flashes more than three times per second: strobing alerts, glitch effects, flickering loaders or video (WCAG 2.3.1). Test: screen-record each animated section and step through it frame by frame
- [ ] `A11Y-017` **P1** An inactivity timeout warns at least 20 seconds before it ends the session and lets the user extend it with one action, unless the limit is essential, such as a timed exam (WCAG 2.2.1). A silent expiry throws away a half-filled form (see `QA-010`, `SEC-009`). Test: make a build with a short timeout, leave a form half filled and wait: a warning appears, one click keeps the session, and nothing typed is lost
