# Java Spring — pre-launch test cases

- [ ] `JAVA-004` **P0** Spring Security config reviewed for permitAll leftovers (concrete test: `JAVA-007`)
- [ ] `JAVA-005` **P1** Flyway/Liquibase migrations tested
- [ ] `JAVA-022` **P0** Error responses carry no stack trace or exception text: production config doesn't set `include-stacktrace`, `include-message` or `include-binding-errors` to `always`, or `include-exception=true` (`server.error.*` up to Boot 3.5, `spring.web.error.*` in Boot 4), and no `@ExceptionHandler` returns `e.getMessage()`, `e.toString()` or a stack trace for unexpected errors. Test: send a duplicate unique value and a too-long string to a write endpoint and read the body (see `BE-004`)
- [ ] `JAVA-023` **P0** Production runs with production settings: no `spring.profiles.active=dev|local` in committed `application.*`, the `Dockerfile` (`SPRING_PROFILES_ACTIVE`), compose files or run scripts; the container starts the built jar (`java -jar`), not `mvn spring-boot:run` / `gradle bootRun`, which turn devtools on; no `spring.devtools.remote.secret`; no secret with a fallback value such as `${JWT_SECRET:changeme}`. Test: the production startup log says `The following 1 profile is active: "prod"`, and without the secret env var the app refuses to start (see `ENV-005`, `DOTNET-021`)
- [ ] `JAVA-024` **P0** Passwords use `BCryptPasswordEncoder` or `PasswordEncoderFactories.createDelegatingPasswordEncoder()`; production code and config have no `NoOpPasswordEncoder`, `{noop}`, `User.withDefaultPasswordEncoder()`, hand-made MD5 / SHA encoders, `InMemoryUserDetailsManager` with literal users, or `spring.security.user.name` / `password`. Test: search for them; the production log has no "Using generated security password" line (see `SEC-002`, `AUTH-009`)
- [ ] `JAVA-025` **P0** Without a login only `/actuator/health` (and `info`) answer: `management.endpoints.web.exposure.include` has no `*`, `env`, `configprops`, `heapdump`, `threaddump`, `loggers`, `mappings` or `shutdown` on the public port, no `show-values: always` or `management.endpoint.health.show-details: always`, and Swagger UI and `/v3/api-docs` are off in production (`springdoc.api-docs.enabled=false`) or behind a login. Before Boot 3.5, exposing `heapdump` alone made it downloadable. Test: logged out on production, request `/actuator`, `/actuator/env`, `/actuator/heapdump`, `/actuator/loggers`, `/v3/api-docs` and `/swagger-ui.html` (see `JAVA-003`, `DOTNET-019`)
- [ ] `JAVA-026` **P0** Thymeleaf prints user content only with `th:text` / `[[…]]`: no `th:utext` or `[(…)]` on anything a user typed unless it went through an HTML sanitizer (OWASP Java HTML Sanitizer). Test: save `<img src=x onerror=alert(1)>` in every text field and open each page that shows it
- [ ] `JAVA-027` **P1** Upload limits fit real files: `spring.servlet.multipart.max-file-size` (default 1MB) and `max-request-size` (default 10MB) are set for the largest real upload (phone photos are several MB), not to `-1`; the proxy allows the same size (nginx `client_max_body_size` defaults to 1m); a too-large file gets a clear 413, not a 500. Test: through the production URL, upload a full-size phone photo and one just over the limit (see `SEC-008`)
- [ ] `JAVA-028` **P1** Behind a proxy or load balancer, `server.forward-headers-strategy=native` is set (Boot sets it only on cloud platforms it detects) with Tomcat trusting only your proxy (`server.tomcat.remoteip.internal-proxies`); `framework` is avoided unless the proxy overwrites `X-Forwarded-For`, because it trusts the leftmost value, which the client controls; no code reads `X-Forwarded-For` by hand. Test: on production, login and OAuth redirects use `https://`, the session cookie has `Secure`, and a fake `X-Forwarded-For` doesn't change the IP in logs or the rate limiter (see `SEC-007`)
- [ ] `JAVA-029` **P1** Spring Boot is on a line that still gets open-source fixes (spring.io/projects/spring-boot#support): in October 2026 that means 4.0.x or 4.1.x, since 3.5.16 (June 2026) was the last 3.x release; it isn't downgraded to 2.x to make old `WebSecurityConfigurerAdapter` code compile. A dependency scan is clean: `mvn org.owasp:dependency-check-maven:check` (Gradle: `dependencyCheckAnalyze`) or `osv-scanner scan source -r .` (see `SEC-010`, `UNI-009`)
